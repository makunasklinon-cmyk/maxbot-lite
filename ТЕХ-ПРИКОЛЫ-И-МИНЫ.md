# Технические приколы и мины: MAX и Telegram Bot API

Конкретные факты про платформы, добытые дорогой ценой на проекте maxbot.
Здесь нет протокольных деталей (кодов сообщений внутреннего сокета MAX,
структуры фреймов) — это сознательно не публикуется. Но сами по себе
факты «вот так это устроено» и «вот тут находится грабля» экономят часы
тому, кто будет разбираться сам.

---

## Мины веб-интерфейса MAX

**Список чатов и история сообщений — виртуализированные.** В DOM
одновременно живёт только видимая часть списка (условно несколько
десятков элементов), остальное не отрисовано вообще, а не просто скрыто.
Если скроллить программно напрямую (задать координату прокрутки), новые
элементы могут не подгрузиться — работает надёжнее прокрутка колесом мыши
или её имитация, а не присвоение свойства напрямую.

**У одного и того же условного «номера элемента» в разметке может быть
несколько DOM-узлов** — один настоящий, другие — невидимые
служебные/технические заглушки. Если искать элемент просто по номеру, есть
риск попасть не в тот узел. Нужно дополнительно фильтровать по признаку
«это настоящее сообщение», а не любое совпадение номера.

**Наведение мышью работает не в любую точку элемента.** Видимый «пузырь»
сообщения может быть заметно уже, чем весь блок элемента в разметке — если
навести в геометрический центр всего блока, можно попасть мимо
реального содержимого. Наводить нужно именно на видимую часть, и часто
одного события наведения недостаточно — требуется имитация двух
последовательных движений мыши, иначе интерфейс не считает это
наведением вообще.

**Реакции (эмодзи) рисуются внутри canvas фоновым процессом страницы** —
в разметке нет ни текста, ни атрибута, который бы говорил, какая именно
это реакция. Прочитать «что нарисовано» через обычный осмотр разметки
невозможно в принципе — canvas не хранит семантику, только пиксели.
Единственный надёжный путь — соотносить действие с тем, что сама
страница загружает или посылает по сети в момент этого действия, а не
пытаться прочитать итоговую картинку.

**Раскрывающиеся длинные панели (например, полный список реакций)
дорисовываются только при прокрутке колесом**, а не при программной
установке прокрутки — даже если высота содержимого больше видимой
области, элемент-скроллер может физически отсутствовать в разметке
традиционным образом.

**Свои технические метки на элементах могут теряться при перерисовке
интерфейса.** Если вешаешь на DOM-элемент собственный атрибут для
последующего поиска — заложи запасной способ найти тот же элемент иначе
(например, по видимому названию), потому что после перерисовки
фреймворком, на котором построен интерфейс, кастомные атрибуты не
гарантированно сохраняются.

**Панель поиска нельзя закрывать до завершения действия с найденным
элементом.** Закрытие панели поиска перерисовывает историю целиком, и
элемент, который ты только что нашёл, снова выгружается из видимой
области.

**Интерфейс может сообщать о событии сразу в нескольких местах.** Прежде
чем городить сложный способ прочитать что-то из глубины интерфейса —
проверь, не показывается ли то же самое проще: счётчиком, значком в
списке, изменением заголовка. Разработчики интерфейса обычно дублируют
важные события туда, где их проще заметить, потому что это нужно и живому
человеку, а не только автоматизации.

**Русская и английская локализация могут прийти в разные дни для одного и
того же аккаунта** без видимой причины. Любой код, который ищет элемент
по конкретному тексту подписи, должен проверять сразу набор возможных
вариантов на разных языках, а не один жёстко зашитый вариант.

## Мины Telegram Bot API

**Команды меню принимают только латиницу.** Русские названия команд
(`/удалить`) Bot API отклоняет с ошибкой при регистрации в меню. Можно
использовать русские слова как алиасы внутри своей логики обработки
сообщений — но в самом системном меню команд должна быть латиница.

**Видимость команд не доходит до топиков внутри супергруппы.** Область
действия команд у Bot API управляется на уровне чата целиком, а не
конкретного топика внутри форума — то есть если у тебя супергруппа с
несколькими темами, меню команд будет одно и то же во всех темах сразу,
разделить его по темам штатными средствами нельзя.

**Bot API не присылает боту событие об удалении сообщения** (обычным
ботам, не аккаунтам корпоративного типа). Если тебе нужно узнать, что
сообщение удалено — Bot API тебе об этом сам не сообщит, это открытая и
давняя проблема самой платформы, а не недоработка твоего кода. Проверено
и обходной путь через опрос статуса раз в период — тоже плохое решение
(дорого и с задержкой), не стоит изобретать его заново, лучше искать
альтернативный признак (например, реагировать на действие пользователя,
а не пытаться поймать событие удаления напрямую).

**Проверить, существует ли ещё сообщение, можно окольным путём** —
попыткой на нём безобидное техническое действие (не меняющее видимый
текст). Если API отвечает «сообщение не найдено» — оно удалено; если
отвечает другой конкретной ошибкой («нельзя редактировать») — оно ещё на
месте. Разные тексты ошибок API в этом случае несут разную информацию,
стоит их различать, а не просто ловить «любую ошибку».

**Отправленные скопом фотографии/видео (альбомы) приходят боту
НЕСКОЛЬКИМИ отдельными обновлениями**, у которых есть общий технический
идентификатор группы — их нужно самостоятельно собирать в одно целое по
этому идентификатору, а не рассчитывать, что альбом придёт одним куском.

**Скачивание файлов через стандартный способ API ограничено небольшим
размером** (порядка 20 МБ). Для больших файлов существует альтернативный
режим работы с локальным сервером Bot API, но включать его нужно с
конкретным флагом — без него ограничение размера остаётся тем же, несмотря
на локальный режим.

**Настоящий числовой идентификатор сообщения можно закодировать прямо в
данные нажатия инлайн-кнопки**, если он в разумных пределах по размеру
(лимит на такие данные у кнопок небольшой, но реальные идентификаторы
сообщений в него помещаются). Тогда не нужно городить отдельную таблицу
соответствий в памяти бота — кнопки продолжают работать даже после
перезапуска бота, потому что вся нужная информация уже лежит прямо в
кнопке.

## Общий урок из обеих платформ

Ограничение платформы — это не всегда баг именно в твоём коде, но и не
повод сразу опускать руки. Почти каждая мина из этого списка имеет
обходной путь — просто он часто не там, где интуитивно ищешь в первую
очередь (внутри объекта, а не снаружи от него; через прямое действие, а
не через окольный признак). Прежде чем писать сложный обходной путь —
проверь, не проще ли посмотреть на проблему с другой стороны.
